# 快速部署命令

项目根目录：`/root/autodl-tmp/video_cut_forigen`

## 端口

| 服务 | 本机端口 | 公网 |
|------|----------|------|
| 路径代理 | `6006` | AutoDL 自定义服务 6006 |
| 语音转写 | `7006` | 经代理：`/v1/asr`、`/v1/asr/health` |
| 清晰度 | `6009` | 经代理：`/v1/vqa` |
| 文字识别 | `6008` | AutoDL 自定义服务 6008 |

## 密钥

```bash
export ASR_API_KEY='01d503268439d1d4647edb144925724029dc93370d13bd52a1f8e70c6f8a49fa'
# 可选：文字识别 / 清晰度单独密钥（不设则复用上面的 ASR_API_KEY）
# export OCR_API_KEY="$ASR_API_KEY"
# export DOVER_API_KEY="$ASR_API_KEY"
```

请求头二选一：`X-API-Key: $ASR_API_KEY` 或 `Authorization: Bearer $ASR_API_KEY`  
语音探活只认 `/v1/asr/health`（本机 `7006` 与公网相同），清晰度公网探活 `/v1/vqa/health`、文字识别 `/health` 不需要密钥。清晰度本机直连仍可用 `/health`。

## 启动（按顺序）

```bash
cd /root/autodl-tmp/video_cut_forigen
export ASR_API_KEY='你的密钥'

# 1) 语音（本机 7006）
conda activate whisper-turbo  
bash scripts/start_asr.sh

# 2) 文字识别（本机 / 公网 6008）
conda activate ocr-pp
bash scripts/start_ocr.sh

# 3) 清晰度（本机 6009，默认 2 路处理器）
conda activate dover
bash scripts/start_dover.sh

# 4) 路径代理（本机 / 公网 6006；须在语音、清晰度之后）
bash scripts/start_proxy.sh
```

每个启动脚本会占住当前终端并自动拉起；可用 `tmux` / `screen` 分窗跑，或后台：

```bash
nohup bash scripts/start_asr.sh   >/dev/null 2>&1 &
nohup bash scripts/start_ocr.sh   >/dev/null 2>&1 &
nohup bash scripts/start_dover.sh >/dev/null 2>&1 &
nohup bash scripts/start_proxy.sh >/dev/null 2>&1 &
```

## 查看是否在运行

```bash
# 1) 探活：能返回 JSON 且 model_loaded 为 true
curl -s -m 2 http://127.0.0.1:7006/v1/asr/health || echo asr_down
curl -s -m 2 http://127.0.0.1:6008/health || echo ocr_down
curl -s -m 2 http://127.0.0.1:6009/health || echo dover_down
curl -s -m 2 http://127.0.0.1:6006/v1/asr/health || echo proxy_down
curl -s -m 2 http://127.0.0.1:6006/v1/vqa/health || echo vqa_via_proxy_down

# 2) 看守望进程是否在（有 pid 文件且进程还活着）
for s in asr_server ocr_server dover_server proxy; do
  f=/root/autodl-tmp/video_cut_forigen/$s/logs/supervise.pid
  if [[ -f "$f" ]] && kill -0 "$(cat "$f")" 2>/dev/null; then
    echo "$s running pid=$(cat "$f")"
  else
    echo "$s not running"
  fi
done

# 3) 看业务进程
ps -ef | grep -E 'asr_server|ocr_server|dover_server|proxy_in_instance' | grep -v grep

# 4) 看端口是否在听
ss -tlnp | grep -E '7006|6008|6009|6006'
```

健康检查里重点看：`model_loaded` / `ready_workers`；清晰度还有 `max_workers`（当前建议 2）。

## 停止

```bash
kill "$(cat /root/autodl-tmp/video_cut_forigen/asr_server/logs/supervise.pid)"
kill "$(cat /root/autodl-tmp/video_cut_forigen/ocr_server/logs/supervise.pid)"
kill "$(cat /root/autodl-tmp/video_cut_forigen/dover_server/logs/supervise.pid)"
kill "$(cat /root/autodl-tmp/video_cut_forigen/proxy/logs/supervise.pid)"
```

只杀业务进程不够：守望脚本会再拉起来。必须杀上面的 `supervise.pid` 对应进程。

确认已停：

```bash
curl -s -m 2 http://127.0.0.1:7006/v1/asr/health || echo asr_down
curl -s -m 2 http://127.0.0.1:6008/health || echo ocr_down
curl -s -m 2 http://127.0.0.1:6009/health || echo dover_down
curl -s -m 2 http://127.0.0.1:6006/v1/asr/health || echo proxy_down
```

## 常用环境变量（可选）

```bash
# 语音
export ASR_PORT=7006
export ASR_MAX_WORKERS=2          # 或改 asr_server/service.conf

# 文字识别
export OCR_PORT=6008
export OCR_MAX_WORKERS=4          # 或改 ocr_server/service.conf
export OCR_DET_BATCH=4
export OCR_REC_BATCH=16

# 清晰度
export DOVER_PORT=6009
export DOVER_DEVICE=cpu
export DOVER_MAX_WORKERS=2        # 或改 dover_server/service.conf；实测 2 路较合适
export DOVER_PYTHON=/root/autodl-tmp/envs/dover/bin/python
```

改 `service.conf` 后需重启对应服务才生效。

## 接口一览

鉴权：业务接口需要密钥；探活不需要。  
表单：`multipart/form-data`，字段 `file`、`task_id`、`source_file_path`（文字识别 `file` 可重复多张）。

### 语音（公网基址 = AutoDL 6006 地址）

| 方法 | 路径 |
|------|------|
| GET | `/v1/asr/health` |
| POST | `/v1/asr` |
| GET | `/v1/asr/{task_id}` |
| POST | `/v1/asr/{task_id}/cancel` |
| POST | `/v1/asr/sync` |

### 清晰度（公网基址 = 同一 AutoDL 6006 地址）

| 方法 | 路径 |
|------|------|
| GET | `/v1/vqa/health`（本机也可用 `/health`） |
| POST | `/v1/vqa` |
| GET | `/v1/vqa/{task_id}` |
| POST | `/v1/vqa/{task_id}/cancel` |
| POST | `/v1/vqa/sync` |

完成时看 `result.technical_score`（0～1 的清晰度正数分，越高越清晰）。

### 文字识别（公网基址 = AutoDL 6008 地址）

| 方法 | 路径 |
|------|------|
| GET | `/health` |
| POST | `/v1/ocr` |
| GET | `/v1/ocr/{task_id}` |
| POST | `/v1/ocr/{task_id}/cancel` |
| POST | `/v1/ocr/sync` |

## 调用示例（本机）

```bash
# 清晰度同步
curl -s -X POST 'http://127.0.0.1:6009/v1/vqa/sync' \
  -H "X-API-Key: $ASR_API_KEY" \
  -F "file=@/path/to/video.mp4" \
  -F "task_id=demo_vqa_001" \
  -F "source_file_path=/path/to/video.mp4"

# 经代理调清晰度（等同公网 6006）
curl -s -X POST 'http://127.0.0.1:6006/v1/vqa/sync' \
  -H "X-API-Key: $ASR_API_KEY" \
  -F "file=@/path/to/video.mp4" \
  -F "task_id=demo_vqa_002" \
  -F "source_file_path=/path/to/video.mp4"

# 语音异步：提交
curl -s -X POST 'http://127.0.0.1:6006/v1/asr' \
  -H "X-API-Key: $ASR_API_KEY" \
  -F "file=@/path/to/video.mp4" \
  -F "task_id=demo_asr_001" \
  -F "source_file_path=/path/to/video.mp4"

# 语音查询
curl -s 'http://127.0.0.1:6006/v1/asr/demo_asr_001' \
  -H "X-API-Key: $ASR_API_KEY"
```
