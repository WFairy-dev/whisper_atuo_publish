# 语音转写、文字识别与视频清晰度服务接口文档

版本：`1.9.0`（语音 `1.8.0` / 文字识别 `1.4.0` / 清晰度 `0.1.0`）  
协议：`HTTP`  
数据格式：请求为表单文件上传，响应为 `JSON`（`UTF-8`）

本文供业务流水线对接使用。调用方在公司内网、不带显卡的机器上发起请求，服务部署在带显卡的机器上。调用方在自己的机器上读取文件，把文件内容放进请求。`source_file_path` 只是记下来的路径文字，服务不会按它打开磁盘。

三个服务各自独立进程，调用方式相同：先提交，再按任务号查询，不需要时取消。

公网入口（AutoDL 自定义服务）：

| 公网映射 | 用途 |
|---|---|
| `6006` | 路径代理。语音走 `/v1/asr*`（探活用 `/v1/asr/health`）；清晰度走 `/v1/vqa*`（探活用 `/v1/vqa/health`） |
| `6008` | 文字识别 |

本机实际监听：语音 `7006`，清晰度 `6009`，文字识别 `6008`，代理 `6006`。

# 一、接口清单

## 1.1 语音转写

基地址：公网 `http://{主机}:{AutoDL的6006映射}`；本机直连可用 `http://{主机}:7006`。

| 接口名称 | 方法 | 路径 | 类型 | 鉴权 |
|---|---|---|---|---|
| 健康检查 | `GET` | `/v1/asr/health` | 同步 | 否 |
| 提交转写任务 | `POST` | `/v1/asr` | 异步 | 是 |
| 查询转写任务 | `GET` | `/v1/asr/{task_id}` | 同步 | 是 |
| 取消转写任务 | `POST` | `/v1/asr/{task_id}/cancel` | 同步 | 是 |
| 同步转写 | `POST` | `/v1/asr/sync` | 同步 | 是 |

推荐使用异步：先提交，再按任务号查询，直到完成。同步接口一次请求阻塞到转写结束，适合短音频或联调。高并发请使用异步接口。

## 1.2 文字识别

基地址：`http://{主机}:6008`（公网为 AutoDL 的 6008 映射）。模型是 `PP-OCRv6_small` 的检测与识别。

| 接口名称 | 方法 | 路径 | 类型 | 鉴权 |
|---|---|---|---|---|
| 健康检查 | `GET` | `/health` | 同步 | 否 |
| 提交识别任务 | `POST` | `/v1/ocr` | 异步 | 是 |
| 查询识别任务 | `GET` | `/v1/ocr/{task_id}` | 同步 | 是 |
| 取消识别任务 | `POST` | `/v1/ocr/{task_id}/cancel` | 同步 | 是 |
| 同步识别 | `POST` | `/v1/ocr/sync` | 同步 | 是 |

## 1.3 视频清晰度

基地址：公网与语音相同，走 AutoDL 的 `6006` 映射；本机直连可用 `http://{主机}:6009`。模型是 `DOVER` 的技术支路（只评清晰度相关的技术质量，不返回美学分）。

| 接口名称 | 方法 | 路径 | 类型 | 鉴权 |
|---|---|---|---|---|
| 健康检查 | `GET` | `/v1/vqa/health`（本机也可用 `/health`） | 同步 | 否 |
| 提交评估任务 | `POST` | `/v1/vqa` | 异步 | 是 |
| 查询评估任务 | `GET` | `/v1/vqa/{task_id}` | 同步 | 是 |
| 取消评估任务 | `POST` | `/v1/vqa/{task_id}/cancel` | 同步 | 是 |
| 同步评估 | `POST` | `/v1/vqa/sync` | 同步 | 是 |

经公网 `6006` 时，语音探活用 `/v1/asr/health`，清晰度探活用 `/v1/vqa/health`。语音不再提供 `/health`。

# 二、公共约定

## 2.1 鉴权与请求头

业务接口必须带密钥。健康检查不需要。未单独设置文字识别密钥 `OCR_API_KEY`、清晰度密钥 `DOVER_API_KEY` 时，二者都使用语音转写的同一密钥 `ASR_API_KEY`。

| 参数名 | 位置 | 是否必填 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|---|
| `X-API-Key` | 请求头 | 业务接口必填 | string | 与部署方约定的密钥 | 与 `Authorization` 二选一 |
| `Authorization` | 请求头 | 与上一行二选一 | string | 密钥的另一种传递方式 | 格式为 `Bearer {密钥}` |
| `Content-Type` | 请求头 | 上传时由客户端自动生成 | string | 上传文件的表单类型 | 必须是 `multipart/form-data`，并带边界。不要手写成 `application/json` |

## 2.2 任务状态

查询、提交受理、同步结果都带两个字段：`status` 是状态码，`status_name` 是对应英文。调用方以 `status_name` 分支，`status` 给需要对数字做判断的程序。

| status | status_name | 含义 | 能不能读结果 |
|---|---|---|---|
| `2` | `queued` | 已受理，还在排队 | 不能，`result` 为 `null` |
| `3` | `running` | 某一路正在计算 | 不能，`result` 为 `null` |
| `0` | `completed` | 处理完成 | 能。语音读 `result.text`、`result.segments`；文字识别读 `result.items`；清晰度读 `result.technical_score` |
| `1` | `failed` | 处理失败 | 不能。看 `error_code` 和 `error_msg` |
| `4` | `cancelled` | 已取消 | 不能。排队中的不会再开算；正在计算的会停 |

## 2.3 时刻与耗时

时刻字段 `created_at`、`started_at`、`finished_at`、`expire_at` 都是北京时间字符串，格式 `2026-10-24 16:19:28.339`。还没发生的时刻为 `null`。

耗时字段是数字，单位已经写在名字里：`audio_duration_s`、`queue_wait_s`、`cost_time_s`，单位秒。`cost_time_s` 只含计算时间，不含排队。

## 2.4 容量、保留与重启

| 项 | 语音转写 | 文字识别 | 视频清晰度 |
|---|---|---|---|
| 单文件上限 | 默认 `500MB` | 单张默认最多 `20MB`，一组默认最多 `100MB` | 默认 `500MB` |
| 单次数量 | 1 个文件，字段名固定为 `file` | 默认最多 `32` 张。字段名是 `file`，可重复，顺序就是结果顺序 | 1 个视频，字段名固定为 `file` |
| 队列上限 | 默认同时排队 `200` 个；超出直接拒绝 | 默认最多等待 `64` 组。满了返回 `503`，可以稍后用同一任务号重试 | 默认最多等待 `64` 个。满了返回 `503`，可以稍后用同一任务号重试 |
| 并发路数 | 由 `asr_server/service.conf` 的 `workers` 决定，默认 `2` 路同时转写，其余排队。本机最多按 `3` 路启动 | 由 `ocr_server/service.conf` 的 `workers` 决定。环境变量 `OCR_MAX_WORKERS` 可临时覆盖 | 由 `dover_server/service.conf` 的 `workers` 决定，建议 `2` 路（处理器）。环境变量 `DOVER_MAX_WORKERS` 可临时覆盖，上限 `8` |
| 批大小 | 无 | 检测默认 `4`，识别默认 `16`，每一路内部都用这两个数 | 无。一路一次只评一条视频 |
| 上传文件 | 推理结束后立即删除，不长期保存 | 算完或取消后删除 | 与语音相同 |
| 结果保留 | 默认 `24` 小时，过期后查询返回不存在 | 与语音相同 | 与语音相同 |
| 服务重启 | 未完成任务会丢失，需要重新提交；已完成结果在保留期内仍可按任务号查询 | 与语音相同 | 与语音相同 |
| 运行设备 | 显卡 | 显卡 | 默认处理器（`cpu`） |

文字识别、清晰度都是：队列只有一条，哪一路空闲就领走队首的下一个任务号，调用方不用指定进哪一路。文字识别每一路内部按批计算；一个任务的图片留在领到它的那一路，不拆开，也不和另一个任务号拼成一批。

## 2.5 任务号

`task_id` 由调用方生成，同一条素材全流程固定不变。

| 约束 | 说明 |
|---|---|
| 字符 | 只能包含字母、数字、下划线、中横线 |
| 长度 | 1～128 |
| 开头 | 文字识别、清晰度要求以字母或数字开头；语音转写按同一字符集校验 |
| 重复提交 | 排队、计算中或已完成时再次提交，返回 `409`。取消或失败后可以用同一个号重新提交 |
| 已存在的任务 | 改变本次请求里的其他参数，不能修改已有任务 |

## 2.6 拒绝时的统一响应

请求被拒绝时，`HTTP` 状态码不是 `200`。同步接口的业务失败除外，见各接口说明。响应体统一为：

| 参数名 | 是否必返 | 数据类型 | 说明 |
|---|---|---|---|
| `task_id` | 是 | string / null | 能识别到任务号时带回，否则为 `null` |
| `status` | 是 | integer | 拒绝时固定 `1` |
| `status_name` | 是 | string | 拒绝时固定 `failed` |
| `error.error_code` | 是 | string | 英文错误码，见第六节 |
| `error.error_message` | 是 | string | 具体原因 |
| `error.retryable` | 是 | boolean | `true` 表示可以稍后用同一任务号再试；`false` 表示不要原样重试 |

```json
{
  "task_id": "req_20261024_003",
  "status": 1,
  "status_name": "failed",
  "error": {
    "error_code": "TASK_ID_EXISTS",
    "error_message": "任务号已存在: req_20261024_003",
    "retryable": false
  }
}
```

查询到任务之后，任务对象里的 `error_code`、`error_msg` 是数字结果码。它和上面 `HTTP` 拒绝用的英文字符串不是同一套。

# 三、语音转写

支持的文件后缀：`.wav` `.mp3` `.m4a` `.flac` `.ogg` `.aac` `.wma` `.mp4` `.mkv` `.webm` `.mov` `.avi`。

视频会在服务端抽出音轨再转写。文件必须带后缀，字段名固定为 `file`。语种由模型自动识别，或由部署方通过 `ASR_LANGUAGE` 固定，无需在请求中传入。

流水线需要拿到结果再进入下一步时，调用方自己循环查询即可，效果等同于同步等待，同时不受网关超时影响。建议查询间隔 `1～2` 秒。调用方总等待时间按视频时长预留，短片可设几分钟，长视频建议数十分钟以上。

## 3.1 提交转写任务

### 3.1.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口名称 | 提交转写任务 |
| 请求方法 | `POST` |
| 请求路径 | `/v1/asr` |
| 是否异步 | 是 |
| 成功受理状态码 | `200` |
| 鉴权 | 需要 |

请求体是表单，不是 `JSON`。文件内容用 `file` 上传。显卡这台机器看不到调用方磁盘，所以不会按 `source_file_path` 去打开文件，这个路径只用于对账和日志。

### 3.1.2 请求参数

| 参数名 | 是否必填 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|
| `X-API-Key` | 是 | string | 密钥，放在请求头 | 与部署方约定的值。也可改用 `Authorization: Bearer {密钥}` |
| `task_id` | 是 | string | 调用方生成的本次请求唯一标识 | 见第 2.5 节 |
| `source_file_path` | 是 | string | 调用方机器上的源文件路径，只用于对账和日志 | 非空；最长 1024 个字符；必须是带目录的单个文件，使用正斜杠，例如 `D:/视频/a.mp4`；不接受文件夹 |
| `file` | 是 | 文件 | 音频或视频的文件内容 | 参数名必须是 `file`；文件名必须带允许的后缀 |
| `strict_filter` | 否 | string | 是否严格过滤可疑文本 | 见下表。省略或留空使用服务端 `ASR_STRICT_FILTER`，默认 `true` |

`strict_filter` 按文本读取：

| 传入值 | 效果 |
|---|---|
| 省略、空字符串、只含空白 | 未指定，使用服务端 `ASR_STRICT_FILTER`，默认 `true` |
| `true`、`1` | 开启严格过滤。忽略大小写和两端空白 |
| `false`、`0` | 关闭严格过滤。忽略大小写和两端空白 |
| 其他取值 | 返回 `422`，且不会保存上传文件 |

开启时：删除置信度极低、无语音概率高且置信度低等片段；异常长、压缩比过高和低置信度重复会触发结构补救。关闭时：保留这些启发式判断中的可疑文本并标记 `ambiguous`（指标缺失时为 `unknown`），不因这些条件重识别或删除。单个任务的显式取值优先于服务默认值。

两种模式都会处理非法时间、明显越界、片段乱序、超过容差的重叠及片段总时长超限。乱序在补救阶段排序，明显重叠保留排序后先出现的有效片段，拒绝后续冲突片段。容差默认 `0.5` 秒，由 `ASR_DURATION_TOLERANCE` 配置。关闭严格过滤不代表返回未经处理的模型原始结果，也不关闭解码器自身的判断。

### 3.1.3 请求示例

这条命令在持有视频的机器上执行。`@` 读出本机文件再发出去。

```bash
curl -X POST "http://{主机}:{端口}/v1/asr" \
  -H "X-API-Key: {密钥}" \
  -F "task_id=req_20261024_003" \
  -F "source_file_path=D:/share/videos/video_003.mp4" \
  -F "file=@D:/share/videos/video_003.mp4"
```

### 3.1.4 同步响应参数

提交成功只表示已受理，不表示转写完成。返回的 `task_id` 就是调用方传入的那个。`HTTP 200` 时字段与第 3.2 节查询响应相同。此时 `status` 为 `2`，`status_name` 为 `queued`，`result` 为 `null`，`finished_at` 为 `null`。

| 参数名 | 是否必返 | 数据类型 | 说明 |
|---|---|---|---|
| `task_id` | 是 | string | 原请求编号 |
| `status` | 是 | integer | 刚受理时为 `2` |
| `status_name` | 是 | string | 刚受理时为 `queued` |
| 其余字段 | 是 | — | 与第 3.2.3 节相同 |

```json
{
  "task_id": "req_20261024_003",
  "status": 2,
  "status_name": "queued",
  "source_file_path": "D:/share/videos/video_003.mp4",
  "file_size_bytes": 6219280,
  "audio_duration_s": 35.8,
  "created_at": "2026-10-24 16:19:28.339",
  "started_at": null,
  "finished_at": null,
  "queue_wait_s": null,
  "cost_time_s": null,
  "expire_at": null,
  "error_code": null,
  "error_msg": null,
  "result": null
}
```

相同 `task_id` 在排队、转写或已完成时再次提交，返回 `409`，错误码 `TASK_ID_EXISTS`。取消或失败后可以用同一个号重新提交。

## 3.2 查询转写任务

### 3.2.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口名称 | 查询转写任务 |
| 请求方法 | `GET` |
| 请求路径 | `/v1/asr/{task_id}` |
| 是否异步 | 否 |
| 成功状态码 | `200` |
| 鉴权 | 需要 |

`HTTP 200` 只表示查到了这条任务。成没完成看 `status` 和 `status_name`。调用方不能只看 `HTTP` 状态码。

### 3.2.2 请求参数

| 参数名 | 位置 | 是否必填 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|---|
| `X-API-Key` | 请求头 | 是 | string | 密钥 | 也可改用 `Authorization: Bearer {密钥}` |
| `task_id` | 路径 | 是 | string | 调用方传入的任务号 | 与提交时相同 |

```bash
curl "http://{主机}:{端口}/v1/asr/req_20261024_003" \
  -H "X-API-Key: {密钥}"
```

### 3.2.3 响应参数

下面这些字段五种状态都有，没有值时为 `null`。

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|
| `task_id` | 是 | string | 调用方传入的任务号 | 与提交时相同 |
| `status` | 是 | integer | 状态码 | `0` 完成 / `1` 失败 / `2` 排队 / `3` 转写中 / `4` 已取消 |
| `status_name` | 是 | string | 状态英文名 | `completed` / `failed` / `queued` / `running` / `cancelled` |
| `source_file_path` | 是 | string | 调用方传入的源文件路径 | 与提交时相同 |
| `file_size_bytes` | 是 | integer | 上传文件大小 | 单位字节 |
| `audio_duration_s` | 是 | number / null | 语音时长 | 单位秒。读不到时为 `null` |
| `created_at` | 是 | string | 入队时刻 | 北京时间，`年-月-日 时:分:秒.毫秒` |
| `started_at` | 是 | string / null | 开始转写时刻 | 还在排队时为 `null` |
| `finished_at` | 是 | string / null | 结束时刻 | 未结束时为 `null` |
| `queue_wait_s` | 是 | number / null | 排队等待 | 单位秒。还没开始转写时为 `null` |
| `cost_time_s` | 是 | number / null | 纯转写耗时 | 单位秒，不含排队。只有 `completed` 才有数字 |
| `expire_at` | 是 | string / null | 这条记录过期时刻 | 北京时间。默认结束后 24 小时。未结束时为 `null` |
| `error_code` | 是 | integer / null | 业务结果码 | 完成时为 `100000`。失败时见第 6.2 节。排队、转写中、取消时为 `null` |
| `error_msg` | 是 | string / null | 结果说明 | 完成时固定 `success`。失败时是具体原因 |
| `result` | 是 | object / null | 转写结果 | 只有 `status_name = completed` 时非空 |

### 3.2.4 转写结果 `result`

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|
| `language` | 是 | string | 识别出的语种 | 如 `en`、`zh` |
| `text` | 是 | string | 整段转写 | 已去掉首尾空白。后面的流程读这一项 |
| `segments` | 是 | array | 按时间切开的每一句 | 可为空数组。按开始时间排列 |
| `rejected_segments` | 是 | array | 被过滤的片段 | 含原始文本、时间和拒绝原因；非法时间用 `null` 表示 |
| `quality_analysis` | 是 | object | 质量处理摘要 | 见下表 |

`segments[]` 每一项：

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|---|---|---|---|---|
| `id` | 是 | integer / null | 片段序号 | 从 0 起。保留模型原始编号，过滤后可能不连续 |
| `seek` | 是 | integer / null | 模型内部定位值 | 业务一般不用 |
| `start_s` | 是 | number | 这句开始时间 | 单位秒，相对整段音频 |
| `end_s` | 是 | number | 这句结束时间 | 单位秒 |
| `text` | 是 | string | 这一句的字 | 已去掉首尾空白 |
| `no_speech_prob` | 是 | number / null | 无语音概率 | 缺失或非有限指标为 `null` |
| `avg_logprob` | 是 | number / null | 平均对数概率 | 缺失或非有限指标为 `null` |
| `compression_ratio` | 是 | number / null | 压缩比 | 缺失或非有限指标为 `null` |
| `words` | 是 | array | 词级对齐结果 | 每项为 `{start, end, word}`，时间单位秒；对齐不可用时为空数组 |
| `quality_status` | 是 | string | 质量状态 | `accepted` / `ambiguous` / `unknown`；拒绝片段为 `rejected` |
| `quality_reason` | 是 | string | 质量状态原因 | 例如 `quality_passed`、`uncertain_speech`、`invalid_range` |

`quality_analysis`：

| 参数名 | 说明 |
|---|---|
| `strict_filter` | 本任务实际生效的布尔值 |
| `audio_duration_s` | 实际解码音频时长，单位秒 |
| `attempts` | 识别次数 |
| `selected_attempt` | 选中的识别次数 |
| `structural_salvage` | 是否在所有识别均结构异常后抢救 |
| `structural_validation` | 每次结构校验记录，含 `attempt` 和 `errors` |
| `retained_segment_count` | 保留片段数 |
| `rejected_segment_count` | 拒绝片段数 |
| `ambiguous_segment_count` | 可疑但保留的片段数 |
| `unknown_segment_count` | 指标不足、无法判定的片段数 |
| `result` | `speech_retained` 或 `no_valid_speech_segments` |

`result.text` 始终由保留片段重建。没有有效语音或全部片段被过滤时，任务仍可 `completed`，此时 `text` 为 `""`、`segments` 为 `[]`。解码失败、模型运行失败，或无法恢复的响应结构异常，则为 `failed`。服务器不执行静音检查，由调用方上传前完成。

词级时间需在片段范围内并保持顺序，词级文本需完整对应片段文本（忽略空白与大小写）。校验失败时整段 `words` 为 `[]`，调用方应使用片段时间。轻微越界裁剪后同样清空词级对齐。词级时间仍是模型估计值。

历史落盘结果可能没有 `1.7.0` 新增字段，客户端应允许缺失。旧客户端若强制把指标设为 `null`、把 `words` 设为空数组，需要修改适配器才能使用新增信息。只消费 `text` 和 `segments` 的调用方仍可使用过滤后的结果。旧业务侧的「单段覆盖 80%」校验也应同步取消，避免有效短语音被退回到不带显卡的机器上处理。


## 3.3 取消转写任务

### 3.3.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口名称 | 取消转写任务 |
| 请求方法 | `POST` |
| 请求路径 | `/v1/asr/{task_id}/cancel` |
| 是否异步 | 否 |
| 成功状态码 | `200` |
| 鉴权 | 需要 |

调用后马上返回，不等待显卡把这一段算完。该接口不需要 `JSON` 请求体。

| 当前状态 | 处理 |
|---|---|
| 排队中 | 从队列摘掉，删除临时文件，状态变为 `cancelled`。不重新加载模型 |
| 正在转写 | 立刻停掉它所在的那一路进程，状态变为 `cancelled`。这一路在后台重新加载模型，其他路继续领队列里的任务。健康检查里 `recovering` 为 `true`，`ready_workers` 会少 1，直到这一路加载完成 |
| 已经是 `cancelled` | 再调一次仍然返回 `cancelled`，`previous_status` 为 `cancelled` |
| 已经成功或失败 | 返回 `409`，错误码 `TASK_ALREADY_FINISHED`，不改已有结果 |
| 任务不存在或结果已过期 | 返回 `404`，错误码 `TASK_NOT_FOUND` |

取消若和完成几乎同时发生，以先落下来的状态为准：已经写成 `completed` 的不再改成取消；还没写成成功的，取消之后到达的结果会被丢掉。

## 3.4 同步转写

### 3.4.1 基本信息

| 项目 | 内容 |
|---|---|
| 接口名称 | 同步转写 |

# 四、文字识别

时刻、排队耗时、计算耗时、错误体外壳、任务状态都和语音转写相同，见第二节。文字识别多两个字段：`image_count` 是这组图片张数，`mode` 是 `det_rec` 或 `rec_only`。完成时读 `result.items`。

图片后缀：`.jpg` `.jpeg` `.png` `.bmp` `.webp`。

一百张图片请按每组最多 32 张分开提交，每组一个新的任务号。一组里的图片会一起按批计算。

# 五、视频清晰度

时刻、排队耗时、计算耗时、错误体外壳、任务状态都和语音转写相同，见第二节。完成时读 `result.technical_score`。

`technical_score` 已换成 0～1 的正数，方便直接比较。它由技术支路原始分按固定中心和尺度标准化后再压进 0～1，不是官方美学与技术融合分。0.5 大约是普通画质，越高通常表示越清晰、压缩伪影越少。按当前这批素材，高于约 `0.65` 更接近优化后的高清；业务侧仍需用自己的素材标定阈值。原始分在 `technical_raw_score`，可以是负数。

视频后缀：`.mp4` `.mkv` `.webm` `.mov` `.avi` `.m4v` `.mpeg` `.mpg`。字段名固定为 `file`。

公网基地址与语音相同（AutoDL `6006` 映射）。本机直连基地址为 `http://{主机}:6009`。下文示例默认写公网路径习惯下的 `{主机}:{端口}`，即代理所在的 `6006` 入口；本机调试可改成 `6009`。

建议查询间隔 `2～3` 秒。约 30 秒的视频，单条推理大约 8～9 秒（2 路处理器、完整模型）。调用方总等待请按排队预留。

# 六、错误码

## 6.1 语音转写的 HTTP 状态码

| HTTP 状态码 | error_code | 出现接口 | 说明 | retryable | 调用方处理 |
|---|---|---|---|---|---|
| `200` | — | 提交、查询、取消、同步完成 | 请求被受理或查到了任务 | — | 仍要看任务里的 `status_name` |
| `400` | `INVALID_REQUEST` | 提交、同步 | 任务号或文件路径不合法，或缺少文件名 | `false` | 改参数后再提交 |
| `400` | `UNSUPPORTED_FORMAT` | 提交、同步 | 后缀不在允许列表里 | `false` | 换成允许的音视频后缀 |
| `401` | `UNAUTHORIZED` | 提交、查询、取消、同步 | 密钥缺失或错误 | `false` | 核对 `X-API-Key` |
| `404` | `TASK_NOT_FOUND` | 查询、取消 | 任务不存在，或结果已超过 24 小时 | `false` | 核对任务号；过期则用新请求重新提交 |
| `409` | `TASK_ID_EXISTS` | 提交、同步 | 这个任务号已经在排队、转写或已完成 | `false` | 换任务号，或等原来的查询结果 |
| `409` | `TASK_ALREADY_FINISHED` | 取消 | 任务已经完成或失败，不能再取消 | `false` | 保持已有结果 |
| `413` | `FILE_TOO_LARGE` | 提交、同步 | 文件超过单文件上限，默认 500MB | `false` | 压缩或切分后再传 |
| `422` | `MISSING_FIELD` | 提交、同步 | 缺少 `task_id`、`source_file_path` 或 `file` | `false` | 用表单把三个字段补齐 |
| `422` | `INVALID_REQUEST` | 提交、同步 | `strict_filter` 不是 `true`、`false`、`1`、`0` | `false` | 改正该字段，或省略它以使用服务默认值 |
| `500` | 见 6.2 | 同步 | 转写过程失败。响应体是任务对象，不是第 2.6 节的拒绝结构 | `false` | 看 `error_code` 和 `error_msg` |

## 6.2 语音转写的业务结果码

查询到任务之后，结果码在任务对象的 `error_code`、`error_msg` 里。排队、正在转写、已取消时，这两项都是 `null`。

| error_code | 名称 | error_msg | 说明 |
|---|---|---|---|
| `100000` | `SUCCESS` | 固定为 `success` | 转写成功，`status_name` 为 `completed` |
| `100102` | `TRANSCRIBE_FAIL` | 具体失败说明 | 模型转写失败，或音频读不出来 |
| `100103` | `WORKER_EXIT` | `推理进程意外退出` | 这一路推理进程自己退出了 |
| `100104` | `DISPATCH_FAIL` | 具体失败说明 | 任务没能下发给推理进程 |

## 6.3 文字识别的 HTTP 状态码

拒绝时的响应外壳与第 2.6 节相同。

# 七、对接注意

1. 上传不要使用 `JSON`。正文类型是表单，文件字段名固定为 `file`。
2. 异步查询返回 `200` 不代表处理成功。完成要看 `status` 为 `0`，并且 `status_name` 为 `completed`。
3. 结果默认只保留 24 小时。业务侧拿到 `result` 后应自行落库。
4. `cost_time_s` 只含计算时间，不含排队。时刻都是北京时间，可以直接看 `created_at` 和 `finished_at`。
5. 同时提交大量任务是允许的，服务会排队。调用方不要因为短时间没完成就重复提交同一文件。
6. 不再需要某条任务时调用取消接口。语音转写、清晰度取消正在计算的任务后，只重新加载它所在的那一路，其他路不受影响。文字识别取消后不重新加载模型。
7. 看到 `cancelled` 不要当成处理成功，也不要当成文件损坏。
8. 公网走 AutoDL `6006` 时：语音用 `/v1/asr*`，探活用 `/v1/asr/health`；清晰度用 `/v1/vqa*`，探活用 `/v1/vqa/health`。文字识别仍走 `6008`。
9. 清晰度的 `technical_score` 是 0～1 的正数分，越高越清晰。原始分在 `technical_raw_score`，可以是负数。阈值需业务侧自行标定。
