# 语音转写服务接口文档

版本：`1.6.0`  
协议：`HTTP`  
数据格式：请求为表单文件上传，响应为 `JSON`（`UTF-8`）

本文供业务流水线对接使用。调用方在公司内网 CPU 机器上发起请求，服务部署在带显卡的机器上。调用方在自己的机器上读取视频，把文件内容放进请求。`source_file_path` 只是记下来的路径文字，服务不会按它打开磁盘。

---

## 1. 基本信息

| 项 | 说明 |
|----|------|
| 服务名称 | 语音转写远程服务 |
| 基地址 | `http://{主机}:{端口}`，默认端口 `6006`，由部署方提供可达地址 |
| 推荐调用方式 | 异步：先提交，再按任务号查询，直到完成 |
| 同步调用方式 | 一次请求阻塞到转写结束，适合短音频或联调 |
| 鉴权 | 业务接口必须带密钥；健康检查不需要 |
| 密钥传递 | 请求头 `X-API-Key: {密钥}`，或 `Authorization: Bearer {密钥}` |
| 单文件上限 | 默认 `500MB` |
| 队列上限 | 默认同时排队 `200` 个；超出直接拒绝 |
| 显卡并发 | 由 `asr_server/service.conf` 的 `workers` 决定，默认 `2` 路同时转写，其余排队。本机最多按 `3` 路启动 |
| 上传文件 | 推理结束后立即删除，不长期保存 |
| 转写结果 | 默认保留 `24` 小时，过期后查询返回不存在 |
| 服务重启 | 未完成任务会丢失，需要重新提交；已完成结果在保留期内仍可按任务号查询 |

### 1.1 接口一览

| 方式 | 路径 | 鉴权 | 用途 |
|------|------|------|------|
| `GET` | `/health` | 否 | 探活 |
| `POST` | `/v1/asr` | 是 | 异步提交，立即返回任务号 |
| `GET` | `/v1/asr/{task_id}` | 是 | 查询异步任务 |
| `POST` | `/v1/asr/{task_id}/cancel` | 是 | 立刻取消排队中或正在转写的任务 |
| `POST` | `/v1/asr/sync` | 是 | 同步转写，阻塞到结束 |

### 1.2 支持的文件后缀

`.wav` `.mp3` `.m4a` `.flac` `.ogg` `.aac` `.wma` `.mp4` `.mkv` `.webm` `.mov` `.avi`

视频会在服务端抽出音轨再转写。文件必须带后缀，字段名固定为 `file`。

### 1.3 任务状态

查询、提交受理、同步结果都带两个字段：`status` 是状态码，`status_name` 是对应英文。调用方以 `status_name` 分支，`status` 给需要对数字做判断的程序。

| status | status_name | 含义 | 能不能读 result |
|--------|-------------|------|-----------------|
| `2` | `queued` | 已受理，还在排队 | 不能，`result` 为 `null` |
| `3` | `running` | 某一路正在转写 | 不能，`result` 为 `null` |
| `0` | `completed` | 转写完成 | 能，读 `result.text` 和 `result.segments` |
| `1` | `failed` | 转写失败 | 不能。看 `error_code` 和 `error_msg` |
| `4` | `cancelled` | 已取消 | 不能。排队中的不会再开算；正在转写的计算已停 |

时刻字段 `created_at`、`started_at`、`finished_at`、`expire_at` 都是北京时间字符串，格式 `2026-10-24 16:19:28.339`。还没发生的时刻为 `null`。

耗时字段是数字，单位已经写在名字里：`audio_duration_s`、`queue_wait_s`、`cost_time_s`，单位秒。

## 2. 公共请求头

| 参数名 | 位置 | 必填 | 说明 |
|--------|------|------|------|
| `X-API-Key` | Header | 业务接口必填 | 与部署方约定的密钥 |
| `Authorization` | Header | 与上一行二选一 | 格式：`Bearer {密钥}` |
| `Content-Type` | Header | 上传时由客户端自动生成 | 必须是 `multipart/form-data`，并带边界。不要手写成 `application/json` |

## 3. 异步接口（推荐）

流水线需要拿到结果再进入下一步时，调用方自己循环查询即可，效果等同于同步等待，同时不受网关超时影响。

建议查询间隔 `1～2` 秒。调用方总等待时间按视频时长预留，短片可设几分钟，长视频建议数十分钟以上。

### 3.1 提交任务

- 方法：`POST`
- 路径：`/v1/asr`

请求体是表单，不是 JSON。文件内容用 `file` 上传。显卡这台机器看不到调用方磁盘，所以不会按 `source_file_path` 去打开文件，这个路径只用于对账和日志。

#### 请求参数

| 参数名 | 是否必填 | 数据类型 | 说明 | 约束 |
|--------|----------|----------|------|------|
| `X-API-Key` | 是 | string | 密钥，放在请求头 | 与部署方约定的值 |
| `task_id` | 是 | string | 调用方生成的本次请求唯一标识 | 非空；同一条视频全流程固定不变；只能包含字母、数字、下划线、中横线；长度 1～128；结果保留期内不能重复提交 |
| `source_file_path` | 是 | string | 调用方机器上的源文件路径，只用于对账和日志 | 非空；最长 1024 个字符；必须是带目录的单个文件，使用正斜杠，例如 `D:/视频/a.mp4`；不接受文件夹 |
| `file` | 是 | 文件 | 音频或视频的文件内容 | 参数名必须是 `file`；文件名必须带允许的后缀 |

语种由模型自动识别，不用传。

#### 请求示例

这条命令在持有视频的机器上执行。`@` 读出本机文件再发出去。

```bash
curl -X POST "http://{主机}:{端口}/v1/asr" \
  -H "X-API-Key: {密钥}" \
  -F "task_id=req_20261024_003" \
  -F "source_file_path=D:/share/videos/video_003.mp4" \
  -F "file=@D:/share/videos/video_003.mp4"
```

#### 异步响应参数（提交成功，HTTP 200）

提交成功只表示已受理，不表示转写完成。返回的 `task_id` 就是调用方传入的那个。

| 参数名 | 是否必返 | 数据类型 | 说明 |
|--------|----------|----------|------|
| `task_id` | 是 | string | 原请求编号 |
| `status` | 是 | integer | 状态码。刚受理时为 `2` |
| `status_name` | 是 | string | 与状态码对应，刚受理时为 `queued` |
| 其余字段 | 是 | — | 与第 3.2 节查询响应相同。此时 `result` 为 `null`，`finished_at` 为 `null` |

```json
{
  "task_id": "req_20261024_003",
  "status": 2,
  "status_name": "queued",
  "source_file_path": "D:/share/videos/video_003.mp4",
  "file_size_bytes": 6219280,
  "audio_duration_s": 35.8,
  "created_at": "2026-10-24 16:19:28.339",
  "started_at": null,
  "finished_at": null,
  "queue_wait_s": null,
  "cost_time_s": null,
  "expire_at": null,
  "error_code": null,
  "error_msg": null,
  "result": null
}
```

相同 `task_id` 在排队、转写或已完成时再次提交，返回 `409`。取消或失败后可以用同一个号重新提交。

### 3.2 查询任务

- 方法：`GET`
- 路径：`/v1/asr/{task_id}`

#### 请求参数

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|--------|------|------|------|------|
| `X-API-Key` | Header | 字符串 | 是 | 密钥 |
| `task_id` | Path | 字符串 | 是 | 调用方传入的任务号 |

#### 请求示例

```bash
curl "http://{主机}:{端口}/v1/asr/5e31ca767bbb4eb5b0494947d902c304" \
  -H "X-API-Key: {密钥}"
```

#### 异步响应参数

HTTP 状态码为 `200` 只表示查到了这条任务。成没完成看 `status` 和 `status_name`。下面这些字段五种状态都有，没有值时为 `null`。

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|--------|----------|----------|------|------|
| `task_id` | 是 | string | 调用方传入的任务号 | 与提交时相同 |
| `status` | 是 | integer | 状态码 | `0` 完成 / `1` 失败 / `2` 排队 / `3` 转写中 / `4` 已取消 |
| `status_name` | 是 | string | 状态英文名 | `completed` / `failed` / `queued` / `running` / `cancelled` |
| `source_file_path` | 是 | string | 调用方传入的源文件路径 | 与提交时相同 |
| `file_size_bytes` | 是 | integer | 上传文件大小 | 单位字节 |
| `audio_duration_s` | 是 | number / null | 语音时长 | 单位秒。读不到时为 `null` |
| `created_at` | 是 | string | 入队时刻 | 北京时间，`年-月-日 时:分:秒.毫秒` |
| `started_at` | 是 | string / null | 开始转写时刻 | 北京时间。还在排队时为 `null` |
| `finished_at` | 是 | string / null | 结束时刻 | 北京时间。未结束时为 `null` |
| `queue_wait_s` | 是 | number / null | 排队等待 | 单位秒。还没开始转写时为 `null` |
| `cost_time_s` | 是 | number / null | 纯转写耗时 | 单位秒，不含排队。只有 `completed` 才有数字 |
| `expire_at` | 是 | string / null | 这条记录过期时刻 | 北京时间。默认结束后 24 小时。未结束时为 `null` |
| `error_code` | 是 | integer / null | 业务结果码 | 完成时为 `100000`。失败时见第 6.2 节。排队、转写中、取消时为 `null` |
| `error_msg` | 是 | string / null | 结果说明 | 完成时固定 `success`。失败时是具体原因 |
| `result` | 是 | object / null | 转写结果 | 只有 `status_name = completed` 时非空 |

`result` 字段：

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|--------|----------|----------|------|------|
| `language` | 是 | string | 识别出的语种 | 如 `en`、`zh` |
| `text` | 是 | string | 整段转写 | 已去掉首尾空白。后面的流程读这一项 |
| `segments` | 是 | array | 按时间切开的每一句 | 可为空数组 |

`segments[]` 每一项：

| 参数名 | 是否必返 | 数据类型 | 说明 | 约束 |
|--------|----------|----------|------|------|
| `id` | 是 | integer / null | 片段序号 | 从 0 起 |
| `seek` | 是 | integer / null | 模型内部定位值 | 业务一般不用 |
| `start_s` | 是 | number | 这句开始时间 | 单位秒，相对整段音频 |
| `end_s` | 是 | number | 这句结束时间 | 单位秒 |
| `text` | 是 | string | 这一句的字 | 已去掉首尾空白 |

### 3.3 对接伪代码

```text
提交文件，拿到 task_id
循环：
  查询 task_id
  若 status_name = completed，读取 result.text / result.segments，进入下一流程
  若 status_name = failed，按 error_code、error_msg 处理，不要重试同一损坏文件
  若 status_name = cancelled，按取消处理，不要当成成功
  若 status_name = queued 或 running，等待 1～2 秒再查
  若业务不再需要这条结果，可调用取消接口
  若超过业务超时，停止查询；需要结果时重新提交
```

可重试的情况：网络中断、`503`、`504`。业务失败（`status = error`）不要对同一文件无限重试。

### 3.4 取消任务

- 方法：`POST`
- 路径：`/v1/asr/{task_id}/cancel`

调用后马上返回，不等待显卡把这一段算完。

- 排队中：从队列摘掉，删除临时文件，状态变为 `cancelled`。不重新加载模型。
- 正在转写：立刻停掉它所在的那一路进程，状态变为 `cancelled`。这一路在后台重新加载模型，其他路继续领队列里的任务。健康检查里 `recovering` 为 `true`，`ready_workers` 会少 1，直到这一路加载完成。
- 已经是 `cancelled`：再调一次仍然返回 `cancelled`。
- 已经成功或失败：返回 `409`，不改已有结果。
- 任务不存在或结果已过期：返回 `404`。

取消若和完成几乎同时发生，以先落下来的状态为准：已经写成 `completed` 的不再改成取消；还没写成成功的，取消之后到达的结果会被丢掉。

#### 请求参数

| 参数名 | 位置 | 类型 | 必填 | 说明 |
|--------|------|------|------|------|
| `X-API-Key` | Header | 字符串 | 是 | 密钥 |
| `task_id` | Path | 字符串 | 是 | 调用方传入的任务号 |

#### 请求示例

```bash
curl -X POST "http://{主机}:{端口}/v1/asr/5e31ca767bbb4eb5b0494947d902c304/cancel" \
  -H "X-API-Key: {密钥}"
```

#### 响应（HTTP 200）

字段与查询接口相同，并多一个 `previous_status`，表示取消前的状态：`queued`、`running`。重复取消已经取消的任务时，`previous_status` 为 `cancelled`。

排队中取消时 `started_at` 为 `null`。正在转写时取消会带上 `started_at`。`result` 为 `null`。

```json
{
  "task_id": "req_20261024_003",
  "status": 4,
  "status_name": "cancelled",
  "previous_status": "running",
  "source_file_path": "D:/share/videos/video_003.mp4",
  "file_size_bytes": 6219280,
  "audio_duration_s": 35.8,
  "created_at": "2026-10-24 16:19:28.339",
  "started_at": "2026-10-24 16:19:30.749",
  "finished_at": "2026-10-24 16:19:31.020",
  "queue_wait_s": 2.41,
  "cost_time_s": null,
  "expire_at": "2026-10-25 16:19:31.020",
  "error_code": null,
  "error_msg": null,
  "result": null
}
```

流水线代码：

```python
from client_example import cancel_asr

```

轮询函数若看到 `cancelled`，会抛出 `TaskCancelled`，不要当成转写成功。

## 4. 同步接口

- 方法：`POST`
- 路径：`/v1/asr/sync`

一次请求上传文件并等待转写结束。服务端默认最长等待 `3600` 秒。调用方和中间网关的超时也要大于预期转写时间，否则会出现客户端先断开、服务端仍在跑的情况。

高并发（例如同时几十路）请使用第 3 节异步接口。

#### 请求参数

与异步提交相同。

与第 3.1 节相同：`task_id`、`source_file_path`、`file` 都必填。

#### 请求示例

```bash
curl -X POST "http://{主机}:{端口}/v1/asr/sync" \
  -H "X-API-Key: {密钥}" \
  -F "task_id=req_20261024_003" \
  -F "source_file_path=D:/share/videos/video_003.mp4" \
  -F "file=@D:/share/videos/video_003.mp4"
```

#### 同步响应参数（成功，HTTP 200）

字段与第 3.2 节完成时完全一致：`status` 为 `0`，`status_name` 为 `completed`，并带 `result`、`cost_time_s`、`expire_at`。

| 参数名 | 是否必返 | 数据类型 | 说明 |
|--------|----------|----------|------|
| `status` | 是 | integer | 完成时为 `0` |
| `status_name` | 是 | string | 完成时为 `completed` |
| `finished_at` | 是 | string | 完成时刻，北京时间 |
| `cost_time_s` | 是 | number | 转写耗时，单位秒，不含排队 |
| `error_code` | 是 | integer | 完成时为 `100000` |
| `error_msg` | 是 | string | 完成时固定 `success` |
| `result` | 是 | object | 与第 3.2 节相同 |

```json
{
  "task_id": "req_20261024_003",
  "status": 0,
  "status_name": "completed",
  "source_file_path": "D:/share/videos/video_003.mp4",
  "file_size_bytes": 6219280,
  "audio_duration_s": 35.8,
  "created_at": "2026-10-24 16:19:28.339",
  "started_at": "2026-10-24 16:19:30.749",
  "finished_at": "2026-10-24 16:19:32.439",
  "queue_wait_s": 2.41,
  "cost_time_s": 1.69,
  "expire_at": "2026-10-25 16:19:32.439",
  "error_code": 100000,
  "error_msg": "success",
  "result": {
    "language": "en",
    "text": "完整转写文本",
    "segments": [
      {
        "id": 0,
        "seek": 0,
        "start_s": 0.34,
        "end_s": 2.38,
        "text": "第一句"
      }
    ]
  }
}
```

同步失败时 HTTP 为 `500`，响应体仍是任务对象，`status` 为 `1`，`status_name` 为 `failed`，并带 `error_code`、`error_msg`。字段含义同第 3.2 节失败响应。

等待过程中若该任务被取消，HTTP 为 `200`，`status` 为 `cancelled`，没有 `result`。

## 5. 健康检查

- 方法：`GET`
- 路径：`/health`
- 鉴权：不需要

```bash
curl "http://{主机}:{端口}/health"
```

对接方只需确认服务可用。关键字段：

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `model_loaded` | 布尔 | `true` 表示至少有一路模型已加载，可以接任务 |
| `accepting` | 布尔 | `true` 表示仍接收新任务 |
| `queue_length` | 整数 | 当前排队数 |
| `max_workers` | 整数 | 配置的同时转写路数 |
| `ready_workers` | 整数 | 当前已经加载好、可以领任务的路数 |
| `running` | 整数 | 当前正在转写的条数 |
| `recovering` | 布尔 | `true` 表示正在重新加载模型（通常是因为取消了正在跑的任务） |
| `api_key_required` | 布尔 | `true` 表示业务接口必须带密钥 |
| `max_upload_mb` | 数字 | 单文件上限（MB） |
| `result_ttl_hours` | 数字 | 结果保留小时数 |

## 6. 错误码

请求被拒绝时，HTTP 状态码不是 `200`，响应体统一为：

| 参数名 | 是否必返 | 数据类型 | 说明 |
|--------|----------|----------|------|
| `task_id` | 是 | string / null | 能识别到任务号时带回，否则为 `null` |
| `status` | 是 | integer | 拒绝时固定 `1` |
| `status_name` | 是 | string | 拒绝时固定 `failed` |
| `error.error_code` | 是 | string | 下面 6.1 的英文码 |
| `error.error_message` | 是 | string | 具体原因 |
| `error.retryable` | 是 | boolean | `true` 表示可以稍后用同一任务号再试；`false` 表示不要原样重试 |

### 6.1 HTTP 状态码

| HTTP 状态码 | error_code | 出现接口 | 说明 | retryable | 调用方处理 |
|-------------|------------|----------|------|-----------|------------|
| `200` | — | 提交、查询、取消、同步完成 | 请求被受理或查到了任务 | — | 仍要看任务里的 `status_name` |
| `400` | `INVALID_REQUEST` | 提交、同步 | 任务号或文件路径不合法，或缺少文件名 | `false` | 改参数后再提交 |
| `400` | `UNSUPPORTED_FORMAT` | 提交、同步 | 后缀不在允许列表里 | `false` | 换成允许的音视频后缀 |
| `401` | `UNAUTHORIZED` | 提交、查询、取消、同步 | 密钥缺失或错误 | `false` | 核对 `X-API-Key` |
| `404` | `TASK_NOT_FOUND` | 查询、取消 | 任务不存在，或结果已超过 24 小时 | `false` | 核对任务号；过期则用新请求重新提交 |
| `409` | `TASK_ID_EXISTS` | 提交、同步 | 这个任务号已经在排队、转写或已完成 | `false` | 换任务号，或等原来的查询结果 |
| `409` | `TASK_ALREADY_FINISHED` | 取消 | 任务已经完成或失败，不能再取消 | `false` | 保持已有结果 |
| `413` | `FILE_TOO_LARGE` | 提交、同步 | 文件超过单文件上限，默认 500MB | `false` | 压缩或切分后再传 |
| `422` | `MISSING_FIELD` | 提交、同步 | 缺少 `task_id`、`source_file_path` 或 `file` | `false` | 用表单把三个字段补齐 |
| `500` | 见 6.2 | 同步 | 转写过程失败。响应体是任务对象，不是上面的拒绝结构 | `false` | 看 `error_code` 和 `error_msg` |
| `503` | `QUEUE_FULL` | 提交、同步 | 排队已满，或服务正在关闭 | `true` | 稍后用同一任务号再试 |
| `504` | `SYNC_TIMEOUT` | 同步 | 这次等待超时，任务可能还在队列里 | `true` | 改用查询接口拿该 `task_id` |

拒绝示例（任务号重复）：

```json
{
  "task_id": "req_20261024_003",
  "status": 1,
  "status_name": "failed",
  "error": {
    "error_code": "TASK_ID_EXISTS",
    "error_message": "任务号已存在: req_20261024_003",
    "retryable": false
  }
}
```

### 6.2 任务结果码

查询到任务之后，结果码在任务对象的 `error_code`、`error_msg` 里。这是数字，和上面 HTTP 拒绝用的英文字符串不是同一套。

| error_code | 名称 | error_msg | 说明 |
|------------|------|-----------|------|
| `100000` | `SUCCESS` | 固定为 `success` | 转写成功，`status_name` 为 `completed` |
| `100102` | `TRANSCRIBE_FAIL` | 具体失败说明 | 模型转写失败，或音频读不出来 |
| `100103` | `WORKER_EXIT` | `推理进程意外退出` | 这一路推理进程自己退出了 |
| `100104` | `DISPATCH_FAIL` | 具体失败说明 | 任务没能下发给推理进程 |

排队、正在转写、已取消时，`error_code` 和 `error_msg` 都是 `null`。

## 7. 对接注意

1. 上传不要使用 JSON。Body 类型是表单，文件字段名固定为 `file`。
2. 异步查询返回 `200` 不代表转写成功。完成要看 `status` 为 `0`，并且 `status_name` 为 `completed`。
3. 结果默认只保留 24 小时。业务侧拿到 `result` 后应自行落库。
4. `cost_time_s` 只含转写时间，不含排队。时刻都是北京时间，可以直接看 `created_at` 和 `finished_at`。
5. 同时提交大量任务是允许的，服务会排队。调用方不要因为短时间没完成就重复提交同一文件。
6. 不再需要某条任务时调用取消接口。正在转写的那条被取消后，只重新加载它所在的那一路，其他路不受影响。
7. 看到 `cancelled` 不要当成转写成功，也不要当成文件损坏。
