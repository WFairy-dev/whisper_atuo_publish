# 文字识别服务本地对接说明

版本：`1.4.0`  
日期：`2026-10-28`  
服务位置：带显卡的 AutoDL 机器，默认端口 `6008`  
本文给本地流水线使用。本地代码助手只读这一份即可改调用，不必再打开服务端仓库。

---

## 0. 交给本地代码助手的修改要求

服务端已经部署好。本地要改的是发起请求、等待结果、取消任务的那段流程。语音转写仍走原来的 `6006`，不要改语音接口。

请在本地代码里找出文字识别调用，按下面的规则改。

1. 调用方式与语音转写对齐：调用方自己生成 `task_id`，`POST` 提交后立刻返回，再用 `GET` 轮询，不需要时 `POST` 取消。
2. 一次请求携带同一视频的一组图片，最多 `32` 张。19 张用一个任务号一次提交。13 张的另一个视频用另一个任务号另一次提交。
3. 服务端不会把两个任务号的图片拼成一次计算，也不会在一次响应里返回两个视频的结果。每个任务号只返回自己那一组，顺序与上传顺序一致。
4. 字段名是可重复的 `file`。旧字段名 `files` 已不存在。
5. 提交成功只表示已排队。识别文字在查询结果的 `result.items` 里，不在提交响应的顶层。
6. 看到 `status_name = cancelled` 按取消处理，不要当成识别成功，也不要当成图片损坏。
7. 保留取消能力。用户或上游不要这组结果时，调用取消接口。取消后轮询必须停。
8. 密钥、请求头与语音相同：`X-API-Key`，或 `Authorization: Bearer {密钥}`。
9. 每一行除了整行文字框，还有 `chars`。每个字符一个框，英文单词里的每个字母也单独一个框。`chars[].text` 是一个字符，顺序与这一行 `text` 一致，空格也在里面。用 `chars[].index` 对应这一行里的下标。字符位置对不齐时，这一行的 `chars` 为 `null`。

旧调用长这样，找到后替换：

```http
POST /v1/ocr
Content-Type: multipart/form-data

mode=det_rec
files=@frame_001.jpg
files=@frame_002.jpg
```

旧的成功响应是顶层直接给结果，没有任务号：

```json
{
  "count": 2,
  "items": [
    {"index": 0, "ok": true, "text": "第一行", "boxes": [], "error": null}
  ]
}
```

这种“发出去就阻塞到整组算完、响应里直接是 `count` 和 `items`”的写法要改掉。新的推荐写法是提交、轮询、可取消。联调短任务时可以用同步接口，同步接口也必须带任务号。

## 1. 一组图片和一个任务号怎么对应

| 场景 | 本地怎么发 | 服务端怎么算 | 本地怎么拿结果 |
|------|------------|--------------|----------------|
| 一个视频 19 张图 | 1 个任务号，1 次请求，里面 19 个 `file` | 只算这 19 张，内部自己分批 | 查询这 1 个任务号，`result.items` 有 19 条 |
| 另一个视频 13 张图 | 另 1 个任务号，另 1 次请求，里面 13 个 `file` | 与上面那组分开算，互不拼接。有空闲的路就同时算 | 查询这另 1 个任务号，`result.items` 有 13 条 |
| 一个视频 40 张图 | 拆成 32 张 + 8 张，两个任务号，两次请求 | 两次各自计算 | 本地按组序把两次数组接起来 |
| 一张图一个请求 | 不要这样发 | 每次只拿到一张，凑不齐一批，更慢 | 结果也会变成很多个任务号 |

两个视频可以连续提交，也可以并行提交。两次提交都会马上返回 `queued`。服务有 3 路，哪一路空闲就领走队首的下一个任务号，调用方不用指定进哪一路。有空闲的路时，几组会同时算；路都占着时，后来的在队列里等。每一组内部仍自己分批。本地要保存两个任务号，分别查询，分别取消。

同一视频不超过 32 张时，不要按张拆任务号。超过 32 张时，每一组一个新任务号，组与组之间的任务号不能相同。

`source_file_path` 填这组图片所属的视频在本地机器上的路径，例如 `D:/视频/a.mp4`。服务端只把这串文字记到日志和结果里，不会按它去打开磁盘。同一个视频路径可以出现在不同任务号上。判重看的是任务号，不是路径。

语音服务和文字识别服务的任务号互不影响，因为端口和存储都分开。同一条视频如果语音已经用了 `req_20261028_003`，文字识别可以继续用别的号，例如 `req_20261028_003_ocr_0`。文字识别自己的两次请求，在结果保留的 24 小时内不能复用同一个还在排队、正在识别或已完成的任务号。

任务号字符规则：

- 长度 1～128
- 只允许字母、数字、下划线 `_`、中横线 `-`
- 第一个字符必须是字母或数字
- 由本地生成并保存，取消时要用同一个号

建议格式：`{业务号}_ocr_{组序号}`，组序号从 0 开始。例如视频 `req_a` 只有 19 张，任务号用 `req_a_ocr_0`。视频 `req_b` 有 13 张，任务号用 `req_b_ocr_0`。

## 2. 服务基本信息

| 项 | 值 |
|----|----|
| 基地址 | `http://{AutoDL可达地址}:6008` |
| 协议 | `HTTP`，上传为 `multipart/form-data`，响应为 `JSON`（`UTF-8`） |
| 推荐方式 | `POST /v1/ocr`，然后 `GET /v1/ocr/{task_id}`，间隔约 1 秒 |
| 同步方式 | `POST /v1/ocr/sync`，一次阻塞到结束。本地和中间网关的超时要大于这组图的耗时 |
| 取消 | `POST /v1/ocr/{task_id}/cancel`，调用后马上返回 |
| 探活 | `GET /health`，不需要密钥 |
| 密钥 | 与语音相同，放在 `X-API-Key` 或 `Authorization: Bearer {密钥}` |
| 单次张数 | 最多 32 |
| 单张大小 | 默认最多 20MB |
| 一组大小 | 默认最多 100MB |
| 队列 | 默认最多 64 组在排队。满了返回 `503`，可用同一任务号稍后重试 |
| 结果保留 | 24 小时。业务侧拿到 `result` 后应自己落库 |
| 服务重启 | 未完成的任务丢失，需要重新提交。24 小时内已完成的结果仍可按任务号查询 |
| 图片后缀 | `.jpg` `.jpeg` `.png` `.bmp` `.webp`。文件名必须带后缀 |

时刻字段是北京时间字符串，例如 `2026-10-28 14:40:01.120`。还没发生的时刻为 `null`。

健康检查里本地只需确认 `model_loaded` 为 `true`、`accepting` 为 `true`，并且 `ready_workers` 等于 `max_workers`。其余字段供排障：`queue_length`、`running`、`det_batch`、`rec_batch`、`api_key_required`。`max_workers` 为 `3`，也是上限。

## 3. 任务状态

本地用 `status_name` 分支。`status` 是对应数字。

| status | status_name | 含义 | 能不能读 result |
|--------|-------------|------|-----------------|
| `2` | `queued` | 已受理，还在排队 | 不能，`result` 为 `null` |
| `3` | `running` | 这组正在识别 | 不能，`result` 为 `null` |
| `0` | `completed` | 这一组算完了 | 能，读 `result.items` |
| `1` | `failed` | 整组失败 | 不能。看 `error_code`、`error_msg` |
| `4` | `cancelled` | 已取消 | 不能。半截结果不会返回 |

某一张图片读失败或识别失败时，整组仍然是 `completed`。看该张的 `ok`。`ok` 为 `false` 时读 `error`，同组其他图片照常在 `items` 里。

整组失败才是 `failed`，`error_code` 为 `100202`，`result` 为 `null`。完成时 `error_code` 为 `100000`，`error_msg` 为 `success`。排队、识别中、已取消时，这两个字段都是 `null`。

## 4. 提交任务

- 方法：`POST`
- 路径：`/v1/ocr`
- 成功时 HTTP `200`，正文是任务对象，`status_name` 为 `queued`

### 4.1 表单字段

| 参数名 | 必填 | 类型 | 说明 |
|--------|------|------|------|
| `task_id` | 是 | 字符串 | 本地生成的任务号，规则见第 1 节 |
| `source_file_path` | 是 | 字符串 | 本地视频路径，只用于对账。非空，最长 1024。必须是带目录的单个文件，用正斜杠，例如 `D:/视频/a.mp4`。末尾不要斜杠，不要传文件夹，不要只传文件名 |
| `file` | 是 | 文件，可重复 | 图片内容。参数名必须是 `file`，重复多次。顺序就是结果顺序。1～32 个 |
| `mode` | 否 | 字符串 | `det_rec` 或 `rec_only`。省略时为 `det_rec` |

`det_rec`：图片是视频帧，服务先找文字框再识别。  
`rec_only`：图片已经是切好的文字行，只做识别。此时这一行的 `box` 为 `null`。`chars` 里的框仍相对这张上传图片，服务端内部的缩放和转正已经还原。

普通视频帧用 `det_rec`。

### 4.2 请求示例

19 张图的视频：

```bash
curl -X POST "http://{主机}:6008/v1/ocr" \
  -H "X-API-Key: {密钥}" \
  -F "task_id=req_a_ocr_0" \
  -F "source_file_path=D:/视频/a.mp4" \
  -F "mode=det_rec" \
  -F "file=@D:/帧/a/frame_001.jpg" \
  -F "file=@D:/帧/a/frame_002.jpg"
```

上面只写了两张，实际把这一组的 19 个 `-F "file=@..."` 都放进同一次请求。13 张的另一个视频再发一次，`task_id` 换成 `req_b_ocr_0`，`source_file_path` 换成那个视频的路径。

### 4.3 提交成功响应

```json
{
  "task_id": "req_a_ocr_0",
  "status": 2,
  "status_name": "queued",
  "source_file_path": "D:/视频/a.mp4",
  "file_size_bytes": 2457600,
  "image_count": 19,
  "mode": "det_rec",
  "created_at": "2026-10-28 15:20:01.120",
  "started_at": null,
  "finished_at": null,
  "queue_wait_s": null,
  "cost_time_s": null,
  "expire_at": null,
  "error_code": null,
  "error_msg": null,
  "result": null
}
```

本地保存 `task_id`。此时还没有文字。

## 5. 查询任务

- 方法：`GET`
- 路径：`/v1/ocr/{task_id}`
- 找到任务时 HTTP `200`。不存在或超过 24 小时时 HTTP `404`

建议间隔 1 秒查询。一组几十张图通常几秒内结束，本地总等待按业务超时来设，例如几分钟。

### 5.1 完成响应

```json
{
  "task_id": "req_a_ocr_0",
  "status": 0,
  "status_name": "completed",
  "source_file_path": "D:/视频/a.mp4",
  "file_size_bytes": 2457600,
  "image_count": 19,

```

字段含义：

| 字段 | 含义 |
|------|------|
| `image_count` | 这次上传的张数 |
| `file_size_bytes` | 这组图片的总字节数 |
| `queue_wait_s` | 排队等待秒数，不含识别 |
| `cost_time_s` | 识别秒数，不含排队 |
| `result.count` | `items` 的条数，等于上传张数 |
| `items[].index` | 对应这次请求里 `file` 的顺序，从 0 开始 |
| `items[].ok` | 这一张是否识别成功 |
| `items[].text` | 这一张全部文字行，用换行拼起来 |
| `items[].boxes[].text` | 一行文字 |
| `items[].boxes[].score` | 这一行的识别置信度 |
| `items[].boxes[].det_score` | 文字框的检测置信度。`rec_only` 时没有这个字段 |
| `items[].boxes[].box` | 这一行的四点，单位像素，顺序为左上、右上、右下、左下。`rec_only` 时为 `null` |
| `items[].boxes[].chars` | 这一行的字符框。没有字符时为 `[]`。这一行有文字但对不齐每个字符时为 `null` |
| `items[].boxes[].chars[].text` | 一个字符，与这一行 `text` 里该位置的字符相同。汉字、字母、数字、标点、空格都是一个字符 |
| `items[].boxes[].chars[].index` | 该字符在这一行 `text` 中的下标，从 0 开始。空格也占一个下标 |
| `items[].boxes[].chars[].box` | 该字符的四点，单位像素，顺序为左上、右上、右下、左下。坐标相对上传的这一张图片，服务端裁切、缩放和转正已经还原 |
| `items[].error` | 这一张失败时的原因。成功时为 `null` |

`chars` 的顺序与这一行 `text` 一致。把每一项的 `text` 按顺序拼起来，就等于这一行的 `text`。英文单词按字母切开，单词中间的几个字母用对应的 `index` 取框。例如 `hello` 里两个 `l` 的下标是 `2` 和 `3`。

空格包含在 `chars` 中，`text` 为 `" "`，同样有 `index` 和 `box`。

字符框会跟着这一行的倾斜走。横排、字距比较均匀时接近字的边界。同一行里字号差很大，或者文字严重弯曲时，框会偏。每个字符没有单独的置信度，置信度仍看这一行的 `score`。

这一行有文字，但字符位置和行文本对不齐时，`chars` 为 `null`。整行的 `text` 和 `box` 仍然返回，此时按整行使用。

画面上没有文字时，这一张仍然 `ok = true`，`text` 为空字符串，`boxes` 为空数组。

本地把 `items` 按 `index` 对齐回自己的帧列表。服务端保证 `index` 与上传顺序一致。

## 6. 取消任务

- 方法：`POST`
- 路径：`/v1/ocr/{task_id}/cancel`
- 无请求体
- 取消成功时 HTTP `200`，马上返回，不等这组算完

排队中的任务会从队列摘掉，临时图片删除，状态变为 `cancelled`。  
正在识别的任务状态马上变为 `cancelled`。当前已经送进模型的那一小批会算完，下一批不再算，半截结果丢掉。这一路的模型保持加载，不重新加载，马上可以领下一个任务。其他路继续算。

响应比查询多一个 `previous_status`，放在 `status_name` 后面：

| previous_status | 含义 |
|-----------------|------|
| `queued` | 取消前还在排队 |
| `running` | 取消前正在识别 |
| `cancelled` | 这个号已经取消过，再调一次仍然是已取消 |

```json
{
  "task_id": "req_a_ocr_0",
  "status": 4,
  "status_name": "cancelled",
  "previous_status": "running",
  "source_file_path": "D:/视频/a.mp4",
  "file_size_bytes": 2457600,
  "image_count": 19,
  "mode": "det_rec",
  "created_at": "2026-10-28 15:20:01.120",
  "started_at": "2026-10-28 15:20:01.180",
  "finished_at": "2026-10-28 15:20:01.400",
  "queue_wait_s": 0.06,
  "cost_time_s": null,
  "expire_at": "2026-10-29 15:20:01.400",
  "error_code": null,
  "error_msg": null,
  "result": null
}
```

```bash
curl -X POST "http://{主机}:6008/v1/ocr/req_a_ocr_0/cancel" \
  -H "X-API-Key: {密钥}"
```

一个视频若拆成多组，取消这个视频时，对每一组还在排队或正在识别的任务号各调用一次。已经完成的组再取消会得到 `409`，保留已有结果即可。

取消和完成几乎同时发生时，以先写下来的状态为准。已经是 `completed` 的不会再改成取消。

取消之后，这个任务号可以再次用来提交新的一组图片。

## 7. 同步接口

- 方法：`POST`
- 路径：`/v1/ocr/sync`
- 表单字段与第 4 节相同

本地一次请求阻塞到结束。服务端默认最长等 `3600` 秒。高并发，或用户需要中途取消时，用第 4～6 节的异步接口。同步请求发出之后，另一个调用仍可以用同一个任务号调取消接口。

| 结束情况 | HTTP | 正文 |
|----------|------|------|
| 完成 | `200` | 任务对象，`status_name = completed`，带 `result` |
| 等待过程中被取消 | `200` | 任务对象，`status_name = cancelled`，`result` 为 `null` |
| 整组失败 | `500` | 任务对象，`status_name = failed`。这不是第 8 节的拒绝外壳 |
| 等待超时 | `504` | 拒绝外壳，`error_code = SYNC_TIMEOUT`。任务可能还在队列里，改用 `GET` 继续查这个任务号 |

```bash
curl -X POST "http://{主机}:6008/v1/ocr/sync" \
  -H "X-API-Key: {密钥}" \
  -F "task_id=req_a_ocr_0" \
  -F "source_file_path=D:/视频/a.mp4" \
  -F "mode=det_rec" \
  -F "file=@D:/帧/a/frame_001.jpg" \
  -F "file=@D:/帧/a/frame_002.jpg"
```

## 8. 拒绝时的错误体

请求没被受理时，HTTP 不是任务本身的状态码，正文是：

```json
{
  "task_id": "req_a_ocr_0",
  "status": 1,
  "status_name": "failed",
  "error": {
    "error_code": "TASK_ID_EXISTS",
    "error_message": "任务号已存在: req_a_ocr_0",
    "retryable": false
  }
}
```

认不出任务号时 `task_id` 为 `null`。`error.retryable` 为 `true` 时，可以稍后用同一个任务号再提交。

| HTTP | error_code | 出现位置 | 本地怎么处理 | retryable |
|------|------------|----------|--------------|-----------|
| `200` | 无此壳 | 提交、查询、取消、同步完成或同步被取消 | 看任务对象的 `status_name` | — |
| `400` | `INVALID_REQUEST` | 提交、同步 | 任务号或路径不合法，或 `mode` 不是 `det_rec` / `rec_only`，或缺少文件名 | `false` |
| `400` | `UNSUPPORTED_FORMAT` | 提交、同步 | 后缀不在允许列表 | `false` |
| `400` | `TOO_MANY_IMAGES` | 提交、同步 | 超过 32 张。本地先拆组 | `false` |
| `401` | `UNAUTHORIZED` | 提交、查询、取消、同步 | 密钥缺失或不对 | `false` |
| `404` | `TASK_NOT_FOUND` | 查询、取消 | 任务号不对，或结果已超过 24 小时 | `false` |
| `409` | `TASK_ID_EXISTS` | 提交、同步 | 这个号正在排队、识别或 24 小时内已完成。去查询原任务，或换新号 | `false` |
| `409` | `TASK_ALREADY_FINISHED` | 取消 | 已经完成或失败。保持已有结果 | `false` |
| `413` | `FILE_TOO_LARGE` | 提交、同步 | 单张超过 20MB | `false` |
| `413` | `GROUP_TOO_LARGE` | 提交、同步 | 一组超过 100MB。再拆小 | `false` |
| `422` | `MISSING_FIELD` | 提交、同步 | 缺少 `task_id`、`source_file_path` 或 `file` | `false` |
| `500` | 任务对象里的 `100202` | 仅同步 | 整组识别失败。读任务对象的 `error_msg` | `false` |
| `503` | `QUEUE_FULL` | 提交、同步 | 排队已满或服务正在关闭。稍后用同一任务号重试 | `true` |
| `503` | `NOT_READY` | 提交、同步 | 模型还在加载。稍后用同一任务号重试 | `true` |
| `504` | `SYNC_TIMEOUT` | 同步 | 这次等待超时。改用查询接口拿该任务号 | `true` |

可重试的情况还有网络中断。业务失败（`status_name = failed`）不要对同一组图片无限重试。

## 9. 本地流程

下面这段是本地要落成代码的流程。两个视频各一组，互不合并。

```text
视频 A 有帧列表 frames_a（19 张），视频路径 D:/视频/a.mp4
视频 B 有帧列表 frames_b（13 张），视频路径 D:/视频/b.mp4

对每个视频：
  按 32 张切组。19 和 13 都只有 1 组
  为每一组生成唯一任务号，例如 req_a_ocr_0、req_b_ocr_0
  POST /v1/ocr
    task_id = 该组任务号
    source_file_path = 该视频在本地的路径
    mode = det_rec
    file = 这一组的每一张图片，按帧序重复
  保存任务号，此时响应只是 queued

并行或先后查询每个任务号：
  GET /v1/ocr/{task_id}
  status_name = completed：按 index 把 result.items 写回该视频的帧
  status_name = failed：记录 error_code、error_msg，这一组不要当成有文字
  status_name = cancelled：这一组停止，不要当成成功
  status_name = queued 或 running：等 1 秒再查
  业务上不再需要这一组：POST /v1/ocr/{task_id}/cancel，然后停止查询

同一视频超过 32 张时：
  组 0 用 {业务号}_ocr_0，组 1 用 {业务号}_ocr_1
  全部组 completed 后，本地按组序号把 items 接成该视频的完整结果
  取消该视频时，取消每一组尚未结束的任务号
```

伪代码：

```python
def recognize_video(frames, video_path, business_id, base_url, api_key, should_stop):
    grouped = [frames[i:i + 32] for i in range(0, len(frames), 32)]
    merged = []
    for group_index, group in enumerate(grouped):
        task_id = f"{business_id}_ocr_{group_index}"
        submit_ocr(group, base_url=base_url, task_id=task_id,
                   source_file_path=video_path, api_key=api_key, mode="det_rec")
        while True:
            if should_stop():
                cancel_ocr(base_url, task_id, api_key=api_key)
                raise TaskCancelled(task_id)
            task = get_ocr(base_url, task_id, api_key=api_key)
            name = task["status_name"]
            if name == "completed":
                merged.extend(task["result"]["items"])
                break
            if name == "cancelled":
                raise TaskCancelled(task_id)
            if name == "failed":
                raise RuntimeError(task.get("error_msg"))
            time.sleep(1)
    return merged
```

`business_id` 本身要符合任务号字符规则。两个视频调用两次 `recognize_video`，传入各自的帧、路径和业务号。

## 10. 可直接放入本地工程的客户端

依赖：`httpx`。把下面保存为本地的 `ocr_client.py` 后，流水线 `from ocr_client import recognize_wait, cancel_ocr, TaskCancelled`。

```python
#!/usr/bin/env python3
"""本地调用 AutoDL 文字识别。提交、查询、取消与语音客户端同一形态。"""
from __future__ import annotations

import time
import uuid
from pathlib import Path
from typing import Any, Optional

import httpx


def _headers(api_key: Optional[str]) -> dict[str, str]:
    if not api_key:
        return {}
    return {"X-API-Key": api_key}


def new_task_id() -> str:
    """仅在本地没有业务号时临时生成。正式流水线应传入自己的任务号。"""
    return f"req_{time.strftime('%Y%m%d_%H%M%S')}_{uuid.uuid4().hex[:8]}"


def upload_filename(file_path: str | Path) -> str:
    """记到结果里的路径文字。统一成正斜杠。"""
    return str(file_path).replace("\\", "/")


class TaskCancelled(RuntimeError):
    """任务已被取消。停止等待，不要把这次调用当成识别成功。"""


def _raise_for_status(response: httpx.Response) -> None:
    if response.status_code == 401:
        raise PermissionError("鉴权失败：请检查密钥")
    if response.status_code == 404:
        raise LookupError("任务不存在或已过期")
    if response.status_code == 409:
        body = response.json() if "json" in response.headers.get("content-type", "") else {}
        err = body.get("error") if isinstance(body, dict) else None
        message = (err or {}).get("error_message") if isinstance(err, dict) else None
        raise RuntimeError(message or "任务号冲突或任务已结束")
    if response.status_code >= 400:
        body = {}
        if "json" in response.headers.get("content-type", ""):
            body = response.json()
        if body.get("status_name") == "failed" and body.get("error_msg"):
            raise RuntimeError(body.get("error_msg"))
        err = body.get("error") if isinstance(body, dict) else None
        message = (err or {}).get("error_message") if isinstance(err, dict) else response.text
        raise RuntimeError(message or f"识别失败 HTTP {response.status_code}")


def _form(paths: list[Path], task_id: str, source_file_path: str, mode: str, handles):
    data = {
        "task_id": task_id,
        "source_file_path": upload_filename(source_file_path),
        "mode": mode,
    }
    files = [
        ("file", (path.name, handle, "application/octet-stream"))
        for path, handle in zip(paths, handles)
    ]
    return data, files


def submit_ocr(
    paths: list[Path],
    *,
    base_url: str,
    task_id: str,
    source_file_path: str,
    api_key: Optional[str] = None,
    mode: str = "det_rec",
    timeout: float = 120.0,
) -> str:
    """上传一组图片。返回的任务号就是传入的那个。此时还没有识别结果。"""
    if not 1 <= len(paths) <= 32:
        raise ValueError("一组图片数量必须是 1～32 张")
    url = f"{base_url.rstrip('/')}/v1/ocr"
    handles = [path.open("rb") for path in paths]
    try:
        data, files = _form(paths, task_id, source_file_path, mode, handles)
        response = httpx.post(url, data=data, files=files, headers=_headers(api_key), timeout=timeout)
    finally:
        for handle in handles:
            handle.close()
    _raise_for_status(response)
    return response.json()["task_id"]


def get_ocr(
    base_url: str,
    task_id: str,
    *,
    api_key: Optional[str] = None,
    timeout: float = 30.0,
) -> dict[str, Any]:
    url = f"{base_url.rstrip('/')}/v1/ocr/{task_id}"
    response = httpx.get(url, headers=_headers(api_key), timeout=timeout)
    _raise_for_status(response)
    return response.json()


def cancel_ocr(
    base_url: str,
    task_id: str,
    *,
    api_key: Optional[str] = None,
    timeout: float = 30.0,
) -> dict[str, Any]:
    """立刻取消该任务。排队中的马上摘掉；正在识别的在当前这一小批算完后停下。"""
    url = f"{base_url.rstrip('/')}/v1/ocr/{task_id}/cancel"
    response = httpx.post(url, headers=_headers(api_key), timeout=timeout)
    _raise_for_status(response)
    return response.json()


def recognize_wait(
    paths: list[str | Path],
    base_url: str,
    *,
    task_id: str,
    source_file_path: str,
    api_key: Optional[str] = None,
    mode: str = "det_rec",
    poll_interval: float = 1.0,
    timeout: float = 3600.0,
) -> dict[str, Any]:
    """提交并轮询直到结束。完成时读取 result['items']。"""
    files = [Path(item) for item in paths]
    missing = [str(path) for path in files if not path.is_file()]
    if missing:
        raise FileNotFoundError("找不到图片: " + "、".join(missing))
    task_id = submit_ocr(
        files,
        base_url=base_url,
        task_id=task_id,
        source_file_path=source_file_path,
        api_key=api_key,
        mode=mode,
    )
    deadline = time.time() + timeout
    last: Optional[dict[str, Any]] = None
    while time.time() < deadline:
        last = get_ocr(base_url, task_id, api_key=api_key)
        name = last.get("status_name")
        if name == "completed":
            return last
        if name == "cancelled":
            raise TaskCancelled(f"任务已取消 task_id={task_id}")
        if name == "failed":
            raise RuntimeError(f"识别失败: {last.get('error_msg')}")
        time.sleep(poll_interval)
    raise TimeoutError(f"等待超时 task_id={task_id} last={last}")


def recognize_sync(
    paths: list[str | Path],
    base_url: str,
    *,
    task_id: str,
    source_file_path: str,
    api_key: Optional[str] = None,
    mode: str = "det_rec",
    timeout: float = 3600.0,
) -> dict[str, Any]:
    files = [Path(item) for item in paths]
    url = f"{base_url.rstrip('/')}/v1/ocr/sync"
    handles = [path.open("rb") for path in files]
    try:
        data, form = _form(files, task_id, source_file_path, mode, handles)
        response = httpx.post(
            url, data=data, files=form, headers=_headers(api_key), timeout=timeout,
        )
    finally:
        for handle in handles:
            handle.close()
    _raise_for_status(response)
    body = response.json()
    if body.get("status_name") == "cancelled":
        raise TaskCancelled(f"任务已取消 task_id={body.get('task_id')}")
    if body.get("status_name") == "failed":
        raise RuntimeError(f"识别失败: {body.get('error_msg')}")
    return body


def recognize_video(
    frames: list[str | Path],
    video_path: str,
    business_id: str,
    base_url: str,
    api_key: Optional[str] = None,
    *,
    mode: str = "det_rec",
    should_stop=None,
) -> list[dict[str, Any]]:
    """一个视频的全部帧。超过 32 张会拆组，每组一个任务号，结果按帧序接好。"""
    files = [Path(item) for item in frames]
    merged: list[dict[str, Any]] = []
    grouped = [files[i:i + 32] for i in range(0, len(files), 32)]
    for group_index, group in enumerate(grouped):
        task_id = f"{business_id}_ocr_{group_index}"
        submit_ocr(
            group,
            base_url=base_url,
            task_id=task_id,
            source_file_path=video_path,
            api_key=api_key,
            mode=mode,
        )
        deadline = time.time() + 3600
        while time.time() < deadline:
            if should_stop is not None and should_stop():
                cancel_ocr(base_url, task_id, api_key=api_key)
                raise TaskCancelled(f"任务已取消 task_id={task_id}")
            task = get_ocr(base_url, task_id, api_key=api_key)
            name = task.get("status_name")
            if name == "completed":
                merged.extend(task["result"]["items"])
                break
            if name == "cancelled":
                raise TaskCancelled(f"任务已取消 task_id={task_id}")
            if name == "failed":
                raise RuntimeError(f"识别失败: {task.get('error_msg')}")
            time.sleep(1)
        else:
            raise TimeoutError(f"等待超时 task_id={task_id}")
    return merged
```

## 11. 改完后建议对一下的行为

1. 19 张放在一次请求里，查询该任务号，`image_count` 为 19，`result.items` 长度为 19，`index` 从 0 到 18。
2. 接着提交 13 张的另一个任务号。两个号的 `items` 不会混在一起，条数分别是 19 和 13。
3. 提交后立刻拿到的是 `queued`，文字在稍后的 `completed` 里。
4. 对一个还在排队或正在识别的任务号调用取消，轮询看到 `cancelled`，并且没有 `result`。
5. 用同一个未过期的已完成任务号再提交，得到 HTTP `409`，`error_code` 为 `TASK_ID_EXISTS`。
6. 超过 32 张的视频被拆成多组，本地按组序接回后，总条数等于帧数。
7. 密钥错误得到 HTTP `401`。健康检查 `GET /health` 不带密钥也能返回。
